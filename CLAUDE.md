# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

QwixBox is an installer for a full VoIP PBX stack on Debian 13: Kamailio (public SIP edge) in front of FreeSWITCH (media/PBX core), with rtpengine, PostgreSQL, Redis and a Bun/Hono API. Regression suites live in `portal/api/tests`, `tests/` (Debian installer and SIP), and `site/worker_test.mjs`. Read `tests/README.md` for prerequisites and destructive-fixture boundaries.

- `install.sh` — master installer. Runs `steps/*.sh` in order. Idempotent: each step's marker in `/var/lib/qwixbox/` holds the SHA-256 of the script that satisfied it, so a step re-runs automatically when its script changes. Flags: `--list`, `--only`, `--from`, `--force`, `--dry-run`, `--menu`, `--configure`, `--quiet`. Logs to `/var/log/qwixbox/`.
- `lib/common.sh` — shared helpers, sourced by every step. `apt_install` only installs what is missing; `write_file` writes from stdin and returns 1 when the content was already correct (so callers can skip a reload); `config_ensure_secret` generates a secret once and persists it. It also sources `lib/detect.sh`, `lib/tui.sh`, `lib/wizard.sh` and the DNS helpers (`lib/dns-cloudflare.sh`, `lib/dns-domainconnect.sh`, `lib/dns.sh`), so every step gets them from its single `. lib/common.sh` line.
- `config.env.example` → `/etc/qwixbox/config.env` (0600). Site config plus generated secrets. **Never rotate a secret on re-run** — every service already holds the old value.
- `steps/` — the numbered step scripts. The number encodes ordering; dependencies flow downwards.
- `resources/freeswitch.service` — systemd unit template. `${PREFIX}` is substituted by sed at deploy time (systemd does not expand shell variables), so keep the placeholder intact.
- `resources/conf/` — every configuration file the steps deploy, one directory per step (`kamailio/`, `nginx/`, `freeswitch/`, …). These were inline heredocs until they got long enough that the shell quoting was doing more harm than the co-location was worth; the reasoning comments moved into the file they describe. See "Config templates" below.
- `resources/lua/` — the call-time scripts, deployed by `31-freeswitch-config.sh`. This is the code that runs while a call is being set up; see "Call-time resolution" below.
- `portal/api/` — Bun/Hono API. Owns every write: Postgres, the Redis cache, and Kamailio's `subscriber`/`domain` tables. Also holds the operator CLIs in `src/cli/`.
- `portal/web/` — React admin portal (Vite, TanStack Router, React Query, Mantine). Built and published by `43-portal-web.sh`.

Steps read their configuration from `/etc/qwixbox/config.env` via `load_config`, and reference repo files through `$REPO_DIR` (set by `lib/common.sh`). Earlier versions cloned this repo onto the target to find `resources/`, which meant a local edit did nothing until pushed — that is gone; the local checkout is used directly.

**Read `docs/status.md` for current evidence and `docs/issues.md` for open findings. `docs/mvp.md` holds the release acceptance gates** — what is proven by having been run, what is merely deployed, and what blocks a shippable product. Read it before assuming a feature works: several areas have complete, deployed code that has never been executed once.

**`docs/design/` holds future designs.** It includes salvaged work from the archived v1 repo (see `docs/v1-retrospective.md`) and the proposed implementation phases. Do not read a table sketch there as something that is in `schema.ts`, and do not treat those documents as a contract: they are notes, and the code wins. `docs/roadmap.md` marks what is actually built.

The operator-facing material lives in `README.md`: per-provider provisioning (GCP, EC2, Vultr), the port list, the feature-code table, the post-install checklist, and a step table mirroring `install.sh`'s `STEPS` array — keep that table in sync when adding a step, and do not restate any of it here. `site/` builds the public Astro site and install-script Worker. `docs/issues.md` tracks current remediation; `docs/changelog.md` records changes and removed files. The old review is retained as historical evidence in `docs/reviews/2026-10-24.md`. Start at `docs/README.md` when maintaining project records.

### Topology this assumes

Kamailio owns the public SIP ports (5060/5061) and does registration, auth and flood control. FreeSWITCH listens only on `127.0.0.1:5080` and trusts what Kamailio forwards (`auth-calls=false` paired with a loopback-only ACL — the pairing is what makes it safe, so do not change one without the other). rtpengine relays all media; FreeSWITCH NAT handling is deliberately off so the two do not both rewrite SDP.

## The recurring failure mode here — read this before adding a check

The same bug has been found in this codebase five separate times: **elaborate, well-commented configuration wired to nothing.** The RBAC role model guarded 2 of ~30 routes; role resolution read a session field that does not exist, so every user was a `member` and a `viewer` could delete extensions; the `apiKey` plugin was unused, broken and live on an internet-facing path; `sendInvitationEmail` was an empty function whose comment described a link that did not exist; a `pg_query_one` helper made a Lua fallback tier look present when nothing called it.

Detailed comments are what makes this hard to see — the prose describes intent so convincingly that the absent enforcement reads as present. So:

- **Make the check structural, not remembered.** `permission` is a *required* option on `crudRoutes` (`portal/api/src/lib/crud.ts`) precisely so a new resource cannot be added without one. Prefer that shape over "remember to add the middleware".
- **Prove a control works by trying to break it.** Every one of the above passed typecheck, lint and build. Sign in as the low-privilege role and attempt the thing it must not do; then re-run the identical sequence after the fix.
- Sub-path routes (`/:id/members`, `/:id/options`, `/:id/password`) are separate Hono apps mounted onto the parent, so they do **not** inherit its `crudRoutes` gate. Each mounts its own `requireTenant` + `requirePermission` — check for both when touching them.
- **A setting nothing enforces goes in `UNENFORCED` (`portal/api/src/lib/capabilities.ts`), not into the UI as a working control.** `crudRoutes`, the tenant and extension routes and `provision-tenant.ts` refuse changes to those fields, and the portal disables its inputs from `GET /api/capabilities`. Wiring a field means deleting its entry in the same change. `portal/web/mock/capabilities.ts` is a copy; `tests/portal-mock.test.ts` fails if it drifts.
- **`useWebphone()` returns null outside mock mode, deliberately.** The drawer is a call timer with no SIP client; it was reachable in production and looked like a placed call (I23). Guard every entry point on the null, and do not give the context a default value — that is what lets typecheck find a new button. A real client replaces the provider in `_app.tsx`.
- A `validate` hook on `crudRoutes` gets `existing`, the pre-update row, and a paired-field check **must** use it. A PATCH carries only the fields being changed, so validating `body` alone sees half a pair as absent and skips the check entirely — that is how a cross-tenant id gets written, by sending it without its type.

## The portal (portal/api, portal/web)

- **A tenant IS a better-auth organization.** `session.activeOrganizationId` is the scope for every request. `requireTenant` (`portal/api/src/middleware/tenant.ts`) refuses to proceed without one rather than defaulting to "all" — an unscoped query here is a data breach, not a bug. This is the isolation boundary; the plan chose API-layer enforcement over Postgres RLS because the API is the only writer.
- **The role comes from the `member` row, re-read on every request** — not from the session. Two reasons, both bugs that happened: `session.activeOrganizationRole` does not exist (so the `?? "member"` fallback fired every time), and `activeOrganizationId` is copied into the session at set-active time, so a removed member kept full access for up to eight hours. One indexed lookup on `(user_id, organization_id)`.
- Roles are defined once in `portal/api/src/auth.ts` via `createAccessControl`, exported as `ROLES`, and enforced by `requirePermission` calling `.authorize()`. Add a permission to the statement, not to a hard-coded role list. An unknown role is refused, never defaulted.
- **No self-service registration**, by design — a portal account administers telephony, so a compromise is toll fraud on a customer's bill. Three layers: nginx 404s `^/api/auth/sign-up`, a `databaseHooks.user.create.before` hook throws unless an in-process flag is set, and `src/cli/create-user.ts` sets that flag. `emailAndPassword.disableSignUp` is **not** usable here — better-auth enforces it in the same handler `auth.api.signUpEmail()` calls, so it would block the CLI too.
- Step 44 creates the first account/tenant when `ADMIN_EMAIL` is configured; there is no fixed default password. Otherwise use `create-user.ts` and `provision-tenant.ts`. Add existing accounts through Users or `add-tenant-user.ts`. Membership mutations go through the serialized custom service; better-auth membership mutation paths remain blocked. Invitations are unavailable and no invitation tokens are logged.
- `42-nginx.sh` gates the SPA with `auth_request` against `GET /internal/session` (200/401, fails closed). Two things there are load-bearing: **`location = /` must exist as an exact match** or the site root falls into the gated prefix and an anonymous visitor 404s at `/` with no way to reach the login page; and `/assets/` must stay public or the login page cannot load its own bundle. The second is an accepted limitation, documented in the README — route names stay readable.
- better-auth reads the client address from **`x-real-ip`, not `x-forwarded-for`**. nginx builds XFF with `$proxy_add_x_forwarded_for`, which appends to whatever the client sent, so a client can prepend a fake address and be rate-limited as that. Without a usable header better-auth falls back to one shared bucket per path, which is worse than no limiter: one attacker locks out every user.
- **nginx's `/api/auth` limit is strict by default, with an exact-path allowlist for routine reads** (session, sign-out, organization list/set-active/role/members). Under one strict zone four portal tabs locked a user out. Add a path to the allowlist only if the portal calls it on every load; a credential, reset or unknown endpoint must stay strict. `tests/nginx-auth-limits.py` checks both directions. better-auth's `customRules` keys must be paths the client actually calls — the reset rule named `/forget-password`, which nothing calls, so it limited nothing.
- **The schema reaches Postgres through `drizzle-kit push --force`.** `schema.ts` and `auth-schema.ts` are the source of truth. Step 41 inventories duplicate exact DIDs before push and audits legacy outbound patterns before starting the upgraded service. Two consequences: `--force` skips confirmation, so a rename or a narrowed column applies destructively to an existing install — which is why step 41 (local Postgres) dumps `qwixbox` to `/var/backups/qwixbox/pre-upgrade/` first, rehearses the push on a `qwixbox_preflight` copy, and refuses `DROP`/`TRUNCATE`/`DELETE`/`SET DATA TYPE` in the rehearsal's output unless the run sets `SCHEMA_ACCEPT_DESTRUCTIVE=1` (I14; never put it in `config.env`); and `drizzle.config.ts` must keep listing `schema.ts` *and* `auth-schema.ts` explicitly, because drizzle-kit parses files rather than following re-exports and would otherwise emit a schema with no auth tables.
- **Every Redis/Kamailio effect of a write goes through `projection_job` (`src/services/projections.ts`), never a direct call after commit.** Calling `syncSubscriber`/`rebuildTenant` after the commit lost the effect whenever a dependency was down: a disabled extension kept its subscriber row and could still register. Use `writeAndPublish` (or `crudRoutes`' required `project`) so the job commits with the change. Jobs re-read state when they run, so give them ids, not data; a new job kind is added in `apply()`. The cache-warm watchdog is the one direct caller, because it is its own retry loop.
- **Removing a table needs a `RETIRED_TABLES` entry in `src/cli/check-schema-tables.ts`.** Step 41 runs it before `db:push`; a table in the database but not the schema otherwise makes `push --force` either prompt (and abort without a TTY, when the same release adds a table) or drop it silently.
- **Kamailio authentication reads `ha1`/`ha1b` with `calculate_ha1=0`; the plaintext `subscriber.password` column stays empty.** Never restore the upstream plaintext-auth defaults. SIP passwords are also provided to FreeSWITCH through the protected directory/cache path. The `*Enc` columns (SIP passwords, voicemail PINs, trunk credentials) are AES-256-GCM in `src/lib/crypto.ts`, stored as `iv:tag:ciphertext` base64; `services/kamailio-sync.ts` decrypts, computes HA1/HA1b and writes only the digest into Kamailio's `subscriber` table. That projection is **one-way** on purpose — our schema wins on disagreement and a rebuild fixes it — which is why it uses its own pool and its own credentials.
- Postgres has both databases: `kamailio` and `qwixbox` (that is the API's, despite the repo name). The systemd unit is `qwixbox-api`, the service account `qwixbox`, the deploy directory `/opt/qwixbox-api`. CLIs must be run from there, not the git checkout — the checkout has neither `.env` nor dependencies.
- React Query v5 tracks which result properties a component reads, so **passing a whole `useQuery` result down to a child breaks the subscription.** Destructure at the call site and pass the fields (`QueryState` in `components/Resource.tsx` takes them separately, with a comment saying why). Also check `isEmpty` against `isSuccess`, not just an empty array — a failed fetch otherwise renders "No trunks yet".
- `bun install` fails for an unprivileged user against a root-owned bun cache. Use `bun_as` from `lib/common.sh`.

## Call-time resolution (resources/lua)

`31-freeswitch-config.sh` binds `mod_lua` as the primary XML handler and `mod_xml_curl` second; bindings fall through, so declining in Lua is how a request reaches the API. Two tiers on purpose:

1. `xml_handler.lua` answers from Redis, reached through `mod_hiredis`. The API writes those keys; Lua only ever reads them. Key shapes are contractual — they are listed in `portal/api/src/services/redis.ts`, and changing one means changing both sides.
2. `mod_xml_curl` → the API → Postgres, for anything the cache does not hold.

- **Bind xml_curl only to sections the API actually serves — `directory|dialplan`.** `configuration` was bound as well, with a comment claiming the API served it; `routes/fs-xml.ts` answers every configuration request with "not found", so it only ever cost an HTTP round trip per section at module load and on `reloadxml`. During an install it produced exactly 12 `[ERR] mod_xml_curl.c:319 Received HTTP error 0` lines, because FreeSWITCH starts at step 30 and the API does not exist until step 41. Reproduced both ways in the container: 12 errors with the binding, 0 without, API stopped in both cases.
- Related, and the reason it went unnoticed: **99-postflight scopes its `[ERR]`/`[CRIT]` count to the current FreeSWITCH run**, because the log appends across restarts and an unscoped count reports errors from a life that has already been restarted away. Compare `substr($0,1,19)` lexicographically against `systemctl show freeswitch -p ActiveEnterTimestamp` rendered as `%Y-%m-%d %H:%M:%S` — mawk is Debian's awk and has no `mktime()`. Require the timestamp prefix in the same pattern: untimestamped console output would otherwise land inside every window, since letters sort above digits.
- **A dialable number belongs to one resource per tenant, across types** (`portal/api/src/lib/numbers.ts`, I19). Per-table unique indexes let a ring group and an IVR both be 600, and the tiers disagreed: the cache's single `qwixbox:num:` key held the IVR, while `fs-xml.ts` asked for ring groups first. `crudRoutes` claims for any table in `DIALABLE` with no opt-in, and `validation.test.ts` fails when a schema table with a `number` column is missing from it, so a new dialable type is caught. Writers outside `crudRoutes` (the extension create) call `claimNumber()` inside their transaction; its advisory lock is what makes concurrent creates in different tables safe.
- **A destination that something points at cannot be deleted** (`portal/api/src/lib/references.ts`, I04). Destinations are (type, id) pairs with no foreign key, and an extension is cached by number. A deleted 101 left its DID pointing at "101", so the next person given 101 got the calls in the warm tier, and the cold tier resolved nothing. A new pointer column, or a new destination type, must be added to `destinationReferences()`, or its target can be deleted out from under it.
- **Every polymorphic destination resolves in one place: `qwixbox.go` (`resources/lua/qwixbox.lua`).** An inbound route, an IVR option, a ring-group failover and both branches of a time condition all point at "an extension, or a ring group, or an IVR, or…", so a new destination type is added there and nowhere else. `qwixbox.go` also increments and enforces `depth` against routing loops (an IVR option pointing at a time condition pointing back); every call-time script therefore takes `[depth]` as `argv[3]` and forwards it. A script that drops it re-opens the loop `MAX_DEPTH` exists to close.
- **There is deliberately no Postgres tier in Lua.** It was planned, half-written (`pg_query_one`), never called, and has been removed. Do not reintroduce it: it would mean reimplementing DID, feature-number and outbound-route resolution in a second language, and the case it was for (cold cache) is now handled by the API's warm watchdog.
- Redis is a **pure cache** (`save ""`, `appendonly no`), so a restart empties it — and `unattended-upgrades` will do that at night. `index.ts` polls a `qwixbox:warm` sentinel every 60s and rebuilds when it is gone; `claimWarm()` uses `SET NX` so multiple API instances produce one rebuild. Without this, every call setup took the HTTP path indefinitely and the tier meant to survive an API outage was silently off.
- **Cache sections publish whole generations atomically** (`publishGeneration` in `services/redis.ts`, R13). A section is built in memory, then one Redis script sets its keys and deletes the section's stale ones, so a reader sees the old generation or the new one, never a tenant with keys missing; a failed build writes nothing. The old `rebuildTenant` purged first, and 260 of 4,281 concurrent reads found no tenant. Stale keys are found with the **enumerated** patterns in `keys.tenantPatterns` / `callFlowPatterns`, never `qwixbox:*:<domain>*`, which would also match a domain that merely starts with this one; a new key shape must be added there or it survives as a ghost. Ring groups, IVRs and time conditions publish together (`cacheCallFlows`) because they share `qwixbox:num:`. Publishers must hold `withTenantLock()`, taken only at the outer level (a job run, the warm watchdog): the stale-key scan precedes the script, and nested locking from a second connection deadlocks.
- **mod_hiredis is patched at build time and must stay patched.** Upstream passes the Redis reply straight into `stream->write_function(stream, response)`, which is printf-style — so the reply *is* the format string. Any cached value containing `%` comes back corrupted: an outbound route pattern `^1[0-9]{10}$` was returned with the `%d` sequences expanded into garbage numbers (248 bytes in Redis, 316 out of `hiredis_raw`), so it never matched and every outbound call died as `UNALLOCATED_NUMBER`. It is also a format-string vulnerability reachable from tenant-controlled data, since patterns, extension names and caller IDs all flow through this cache. `30-freeswitch.sh` rewrites it to `write_function(stream, "%s", response)` behind a grep guard. If that guard ever warns, check upstream before assuming it is fixed.
- **Outbound carrier selection happens in FreeSWITCH, not Kamailio.** The Lua matches `outboundRoute.pattern` (a regex) against the number as dialled, applies strip/prepend, and passes the chosen carrier in `X-Trunk-Target`; `route[TOTRUNK]` rebuilds the R-URI around it. There is no `drouting` module and the `dr_*` tables are not created. An earlier design had `do_routing()` reading `dr_gateways`/`dr_rules` with nothing populating them, so every outbound call answered 404 — and the schema comments described the projection as if it existed. Do not reintroduce drouting without removing the Lua path: `dr_rules` matches prefixes and cannot express the regex, and by the egress pass the original dialled number is gone.
- **Endpoints register to Kamailio, so FreeSWITCH holds no registrations.** `route[REGISTRAR]` calls `save("location")` and exits — the REGISTER never reaches FreeSWITCH. The stock directory dial-string `${sofia_contact(...)}` therefore resolves to nothing, and every call to an extension failed with `USER_NOT_REGISTERED`: colleague-to-colleague and every inbound DID once it reached its destination. The dial-string now sends the call back out to Kamailio (`sip_route_uri`, R-URI left as `user@domain`) and `route[TOSUBSCRIBER]` does the `lookup("location")`. **The dial-string exists in two places** — `resources/lua/xml_handler.lua` and `portal/api/src/routes/fs-xml.ts` (the xml_curl fallback tier) — and they must stay identical, which is why both read the egress address from configuration rather than hard-coding it.
- **A call from Kamailio arrives in the `default` context, not its tenant's** (I27). `user_context` is applied only when FreeSWITCH authenticates the caller, and `auth-calls=false` means it never does — and mod_dialplan_xml ignores an answer in any context but the one it asked for (`Hunt-Context`). Both tiers therefore answer a request from any other context with a `transfer` into `tenant_<org>`. Until that existed, every endpoint call ended `NO_ROUTE_DESTINATION`, and nothing had noticed because no test had placed a call through Kamailio. The same applies to anything else set as a directory variable: it does not reach the A-leg.
- **Outbound caller ID is route override → extension → tenant default, in both tiers** (I03), built by `outboundCallerId()` in `services/call-state.ts`. The warm tier reads it from the caller's `qwixbox:call:` profile and declines to the API when that is missing, rather than presenting the bare extension number to a carrier.
- **A forward is authorized by the tenant, never by the caller** (R11). Before `qwixbox.go` transfers an external destination it sets `qwixbox_forward_to`/`_domain`/`_from`. Channel variables cannot be set from SIP (headers arrive as `sip_h_*`), and both tiers treat a lookup whose destination equals `qwixbox_forward_to` as a forward in that tenant. That is the only way a trusted-peer (carrier) call reaches outbound routing or an extension; otherwise a peer reaches exact DIDs only. The forwarding extension, passed to `qwixbox.go` as `via`, places the leg: its caller ID, its `X-Auth-User` and so its Kamailio concurrency bucket. Without `via` (a DID, IVR option or failover pointing at an external number), the tenant default is used and the Lua tier declines to the API. Peer forwards are always API-served; per D5 they check API health first and fail with reorder tone and a 5xx. A new caller of `qwixbox.go` that forwards on an extension's behalf must pass `via`.
- **An emergency call skips Kamailio's ingress fraud checks only by its tenant's projected patterns** (I02). FreeSWITCH identifies an emergency route after the ingress pass, so `route[INGRESS]` asks `route[EMERGENCY]`, which matches `$rU` with `pcre_match` against `emergency=><domain>[i]`. That htable is loaded from Kamailio's `emergency_pattern`, which the `emergency` projection writes. The patterns come from `eligibleOutboundRoutes()` (`services/outbound-routes.ts`), the same definition the Redis tier and `fs-xml.ts` route with. Change eligibility there, never in one tier. Anything else that changes eligibility must queue `{ kind: "emergency" }` (trunk and domain jobs already refresh it). Only `$au` callers are exempt; peers and FreeSWITCH never are.
- **Kamailio recognises FreeSWITCH by address AND source port** (`route[FROMFS]`, I28): UDP from `FS_HOST` on the internal (5080) or external (5081) profile port. Address alone trusted every local process, which could reach a carrier through the egress listener with forged `X-Auth-User`/`X-Tenant-ID` headers. Both profiles bind `transport=udp`, because a TCP connection would leave from an ephemeral port; do not re-enable TCP there. A new FreeSWITCH profile that talks to Kamailio needs its port added to `route[FROMFS]`. Test SIP clients still send from the container's own address (`hostname -I`), as the harnesses do.
- `is_domain_local()` is what separates an internal call from a carrier-bound one on the egress pass, so the `domain` module's in-memory cache must be reloaded when a tenant is added. It has **no `db_mode`**; `reloadKamailio()` issues `domain.reload` for exactly this reason.
- **`kamcmd` exits 0 even when it cannot open the control socket.** The API's service account was not in the `kamailio` group and the socket was `0600`, so every `permissions.addressReload`, `dispatcher.reload` and `domain.reload` failed silently — a trunk or tenant change did not take effect until Kamailio was restarted. Fixed with `modparam("ctl", "mode", 0660)` plus group membership in `41-api-deploy.sh`; `reloadKamailio()` now inspects the output rather than the exit status — **both streams** (I30): a socket error goes to stderr, but an RPC error such as `error: 500 - ongoing reload` goes to stdout. permissions and dispatcher refuse a reload within 5s of the previous one, so two trunk changes in quick succession lost the second until `kamcmdFailed()` read stdout and let the projection retry. If you add a reload, check its output.
- **Only a wrong password counts towards an IP ban** (I29). `route[AUTHRESULT]` reads the authorize result: -1 (database error) answers 503 `Retry-After` and is not counted; only -2/-3 reach `route[AUTHFAIL]`; a stale nonce just re-challenges. Counting every failed authorize meant a database outage banned every address that retried, an office behind NAT for five minutes after the database was back, and only a Kamailio restart cleared it. Separately, **never do arithmetic on `$sht`**: `$sht(t=>k) + 1` concatenates once the item is a string (1, 11, 111), which banned at the second failure and refused an account's third call. Use `$shtinc`/`$shtdec` on a table with `initval=0` (without it `$shtinc` will not create the key and returns 0). `tests/sip-auth.py` runs the deployed blocks and refuses `$sht` arithmetic.
- Rebuild the R-URI as `$rU + "@" + target`, not just `$du`. Setting only the destination URI sends the packet to the carrier while leaving the R-URI pointing at our own egress port, and carriers reject an R-URI whose host is not theirs.
- **Module load order decides which XML tier answers, and it is not the order in `FS_AUTOLOAD_ADD`.** `mod_lua` and `mod_xml_curl` each bind an XML search handler when they load; FreeSWITCH consults bindings in registration order and the first non-empty answer wins. The autoload sed inserted each module directly after the `<!-- Codec Interfaces -->` marker, which *reverses* the list — so `mod_xml_curl` ended up above `mod_lua` and the API answered every lookup. `extension.lua` never ran (no DND, no forwarding, no call waiting, no voicemail treatment) and the Redis tier was bypassed on every call. `31-freeswitch-config.sh` now inserts the block once, in declared order, and **asserts** `mod_lua` precedes `mod_xml_curl`.
- **`mod_curl`'s `curl` API is not the curl command line.** Its grammar is `curl <url> (content-type <t>|timeout <s>|append_headers <name:value>|…) (get|post|… <data>)`. Flags like `-X`, `-H`, `-u`, `-d` are parsed as part of the URL and silently ignored — so requests went out as unauthenticated GETs and every feature code (`*72`, `*90`, DND) and fax notification failed with "unauthorized". Use `qwixbox.api_post()` in `resources/lua/qwixbox.lua`; nothing else should build a curl string. `append_headers` also splits on whitespace, so it cannot carry `Authorization: Basic <b64>` — the secret travels in `X-Gateway-Secret`, which both `/fs/feature` and `/fs/fax` accept alongside Basic (mod_xml_curl sends real Basic natively).
- **A destination of type `extension` must be cached as the extension NUMBER, not its id.** `extension.lua` is keyed by number throughout — `qwixbox:call:<domain>:<number>`, `bridge user/<number>@<domain>`, and the voicemail mailbox. `destinationNumber()` in `services/call-state.ts` does that translation everywhere a destination pair is cached (DIDs, ring-group failovers, IVR timeouts and options, both time-condition branches); every other type is addressed by its own id. The bug hid because `routes/fs-xml.ts` does the same resolution in SQL, so an inbound DID worked while the identical destination behind an IVR option or ring-group failover did not.
- **An `external` destination is an outbound call and must re-enter the dialplan.** `qwixbox.go` transfers rather than bridging to the egress port: bridging skipped outbound route matching entirely, so no trunk was selected, no `X-Trunk-Target` was set, and Kamailio 404'd every forwarded call. The hop count rides across the transfer in the `qwixbox_depth` channel variable, because a transfer restarts the dialplan and `argv` does not survive it — without it a forwarding loop never reaches `MAX_DEPTH`.
- The minimal config ships **no `lang/` tree and no `languages` section**, and neither `mod_say_en` nor `mod_tone_stream` is autoloaded by default. Without them every prompt fails (`Open of languages and phrases failed`) and `silence_stream://` / `tone_stream://` return `Invalid file format` — which is voicemail, IVR and every feature-code tone. `31-freeswitch-config.sh` installs `lang/en` from the vanilla tree and adds the section.
- **When testing anything the XML handler produces, run `fs_cli -x xml_flush_cache` between phases.** FreeSWITCH's own directory cache will serve the previous answer and turn a real failure into a passing test — this produced a false positive during the cache-resilience work.
- `strftime_tz`'s format string must not contain `|` — it is parsed as an epoch delimiter. `time_condition.lua` uses commas.
- A time-condition rule with `invert` must **break** the loop when it matches. Continuing lets a later matching rule overwrite the exclusion, which silently re-opens a holiday.
- The `limit` *application* hangs up on exceed, so it cannot be used to detect call waiting — an answered call is a billed call. Read the count with the `limit_usage` API, decide, then increment with a bare `limit`.
- **The caller is on a call too** (I06). Both tiers start every tenant-context answer for an authenticated caller with `limit hash <domain> <caller>`, the counter call waiting reads; without it, call waiting off still rang an extension placing an outbound call. mod_hash counts once per channel, so re-entry after a transfer is safe. Keep the two tiers identical.
- **A ring group bridges `user/` legs itself, so `extension.lua` never runs for a member** (I05). `ring_group.lua`'s `available()` applies the member's DND and call waiting from the same call profile and `limit_usage` counter, and each leg counts on answer (`execute_on_answer=limit`). A new per-extension call rule must be applied there too, or a group bypasses it. For sequential and random groups, `ringTimeoutSec` is per member via `leg_timeout`: `call_timeout` bounds the whole bridge, and with it alone only the first member ever rang.
- Feature codes are matched **before** the directory so a tenant cannot shadow one with an extension, and the subject is the authenticated user from `X-Auth-User`, never `From:`. Escape codes before using them as patterns — `^*97$` is invalid PCRE (`regex_escape` in `xml_handler.lua`).
- Internally dialled feature numbers (600 for a ring group, 700 for the attendant) need the `qwixbox:num:` index, checked after the directory. Without it a dialled 600 is neither an extension nor a DID and dies as `UNALLOCATED_NUMBER`.

## Validating changes

Static checks first — but do not stop there. `tests/ci.sh shell|api|web|site|integration|sip` runs every check exactly as CI (`.github/workflows/ci.yml`) does. The last two need disposable services and refuse any database not named `*_test`. Add a new check there, not to the workflow, so a local run reproduces CI. `bash -n` and `shellcheck` both pass clean on scripts that fail several different ways at runtime:

```sh
bash -n install.sh
shellcheck install.sh

# Portal, when it was touched. TanStack's route tree is generated, so typecheck regenerates it
# (`bun run routes` regenerates it alone, for when it is stale mid-edit).
cd portal/api && bun run typecheck
cd portal/api && bun run format:check                  # read-only Prettier check
cd portal/web && bun run typecheck && bun run lint && bun run build
```

TypeScript is pinned as an API devDependency. Install locked dependencies before running checks.

Two other portal commands need setting up before they work. Any `drizzle-kit` command (`db:generate`, `db:push`, `db:studio`) reads `DATABASE_URL` and `drizzle.config.ts` throws without it — the installer writes one into `/opt/qwixbox-api/.env`, so local work needs a `portal/api/.env`. `typecheck` does not, which is why the failure only shows up when you reach for drizzle. And `src/db/auth-schema.ts` is **committed, not generated at deploy, and is the generator's output byte for byte** (I24). After changing a better-auth plugin or field, run `bun run auth:generate`; `bun run auth:check` (in CI) fails on any drift. Both use the `auth` package at the installed better-auth version, because the old unpinned `@better-auth/cli` stops at 1.4. Review what the new file changes, because `push --force` applies every difference to live installs. **better-auth's tables have no `created_at` default**: an insert of our own into `organization` or `member` must set `createdAt`, or it fails NOT NULL. A blind regeneration once failed every tenant create that way.

Real verification is an end-to-end run in a Debian 13 systemd container (~2 min on 12 cores). This is the only thing that catches missing dev libraries, modules that fail to load at boot, and service start-up problems.

```sh
# Image: debian:13 + systemd systemd-sysv sudo ca-certificates git procps, CMD ["/sbin/init"]
docker run -d --name fs-test --privileged --cgroupns=host \
  -v /sys/fs/cgroup:/sys/fs/cgroup:rw --tmpfs /run --tmpfs /run/lock <image>

# Seed the clone so the run tests LOCAL changes: clone from GitHub into
# /usr/src/qwixbox, copy the working tree over it, then commit. Being one commit
# ahead makes the script's `git pull --ff-only` a no-op ("Already up to date") instead of
# reverting the changes under test.

docker exec -d fs-test bash -c '/root/install.sh >/var/log/fs.log 2>&1; echo $? >/var/log/fs.exit'
```

Assertions worth making afterwards — each of these has caught a real bug:

- exit code is 0 and `$PREFIX/bin/freeswitch` exists
- every `FS_ENABLE_MODULES` entry is present in `$PREFIX/mod/`, every `FS_DISABLE_MODULES` entry is absent
- `systemctl is-active freeswitch`, and `$PREFIX/run/freeswitch.pid` matches `systemctl show freeswitch -p MainPID`
- `fs_cli -x status` responds, and `fs_cli -x "show codec"` lists Opus
- **zero `[ERR]`/`[CRIT]` in `$PREFIX/log/freeswitch.log`** — a successful build does not imply a clean boot
- re-running the script over the finished install exits 0 again (it is meant to be idempotent)

For portal changes, in the same container:

- anonymous: `/` is the login page, the app routes 404, `/api/*` 401, `/health` returns **JSON not HTML**, `POST /api/auth/sign-up/email` 404
- signed in: a deep-link refresh on `/trunks` returns the app rather than 404 — the whole `auth_request` design exists to make that hold
- **a low-privilege role is refused what it must not do.** Sign in as `viewer` and attempt a trunk create; a `400` for a missing field means the gate passed and validation ran, a `200` means it did not
- CLIs run from the deployed directory: `cd /opt/qwixbox-api && sudo -u qwixbox bun run src/cli/create-user.ts ...`

Copying the working tree into the container with `tar` **does not delete files that moved** — a stale route file left behind by a rename will keep being served and looks like a product bug. Remove the target directory first when route files have moved.

**Architecture caveat — this has already caused a production failure.** On Apple Silicon the container is arm64; the servers are x86_64 (Google Cloud C4). An arm64 pass is not a general pass. The concrete case: libvpx needs an external assembler (yasm/nasm) for its SSE/AVX paths on x86_64, but uses NEON intrinsics via gcc on arm64 and never asks — so a missing assembler is *completely invisible* on arm64 and fails the build on a real server. Any change touching apt dependencies or `./configure` flags should be re-run on amd64:

```sh
docker run -d --platform linux/amd64 ... # same recipe, ~5x slower under emulation
```

Known limitation of the emulated amd64 container: **its systemd is broken** — journald, sysusers, sysctl and tmp.mount all fail, and `systemd-run /bin/sleep 300` fails too. So an amd64 run verifies the *build* (dependencies, configure flags, modules) but cannot verify the service. Start FreeSWITCH manually there (`sudo -u freeswitch $PREFIX/bin/freeswitch -ncwait -nonat`) to check runtime behaviour, and rely on the arm64 container for the systemd unit. Kill leftover instances between manual runs or the log fills with spurious `Could not listen` / `Error Creating SIP UA` port conflicts.

## The interactive layer (wizard, menu, progress)

- **Everything interactive is gated on `tui_available`** (`lib/tui.sh`), which is false without a TTY or without whiptail. That gate is what keeps every automated run — all of the container verification — on the existing `needs_config`/exit-78 path. A wizard that prompts in CI hangs the run forever, so never call a widget without checking it first.
- **`install.sh` redirects stdout into a `tee` pipe** (`exec > >(tee -a "$LOG_FILE")`). Anything written to stdout after that lands in the log file as well as the screen. `exec 3>&1` saves the real stdout beforehand — interactive output belongs on fd 3. This is why there is no spinner: step output scrolls to the same terminal and would fight an in-place progress line, so progress is a `[7/27 26%]` prefix on the step line instead, which is useful in the log too.
- `[ -t 1 ]` is evaluated at the top of `install.sh`, *before* the tee redirect, and cached in `IS_TTY`. Testing it after the redirect always says "not a terminal".
- **The menu (`--menu`) re-executes `install.sh` with the flag each choice maps to.** It has no step-running code of its own on purpose — a second execution path would drift from the CLI, and the CLI is what every automated run uses. Its step list is built from the same `STEPS` array.
- `config_set` rewrites the file line by line rather than with `sed -i "s|^KEY=.*|...|"`. The old form interpolated the value into the replacement, so a `|`, an `&` or a backslash corrupted the file — harmless for generated secrets (alphabet `A-Za-z0-9`), not harmless once the wizard feeds it an SMTP password. It also escapes `\`, `"`, `$` and backtick for the double-quoted context, because the file is read with `set -a; . config.env`.
- **A function whose stdout is its return value must send diagnostics to stderr.** `cf_zone_for_name` prints the zone id on stdout and is captured with `$( )`; an `info` line on stdout was concatenated into the id and every subsequent API path was built from the result.
- `valid_timezone` checks `timedatectl list-timezones` *and* falls back to `/usr/share/zoneinfo`. The list is empty without a system bus (containers, minimal installs), and an earlier version treated "empty list" as "accept anything".

## DNS (lib/dns.sh, steps/02-dns.sh)

- `lib/dns.sh` dispatches manual, Cloudflare and Domain Connect modes. Cloudflare publication is implemented; Domain Connect discovery/approval code exists but provider onboarding and record creation remain unverified. Check current DNS failure/mode issues in `docs/issues.md` before extending this path.
- **Cloudflare returns HTTP 200 with `"success": false`** for many errors, including an out-of-scope token. `cf_api` checks the body, not the status; checking the status alone reports a failed change as a successful one.
- `cf_zone_for_name` walks the name's parent domains until one is a zone the token can see. That walk *is* the ownership check: a token that cannot see any parent does not control the name, and the step stops rather than guessing. Walking rather than assuming the last two labels, because `acme.co.uk` is a three-label zone.
- **Resolve the DNS mode with `dns_resolve_mode`, never `$(dns_mode)`** (I11): the cache lives in a variable, so a command substitution loses it and `auto` re-probes the network on every call. `dns_publish` never fails a step - a record the provider refuses is queued, and `dns_commit` prints it and returns 1 - so keep callers as `dns_commit || warn`.
- **certbot applies `/etc/letsencrypt/cli.ini` over every certificate's own renewal config.** Step 42's webroot `cli.ini` is what moves an HTTP-01 certificate from standalone to nginx's webroot. Written on a DNS-01 host, it made `renew` use webroot (checked with certbot 4.0), so it is HTTP-01 only. Put nothing challenge-specific in it.
- `02-dns.sh` must stay ordered before `13-tls-certs.sh` — Let's Encrypt validates against whatever the name resolves to.
- The A record is written with `proxied=false` and must stay that way. Cloudflare's proxy only handles HTTP; an orange-cloud record would advertise Cloudflare's address to endpoints that need to reach this host for SIP and RTP.

## Mail (steps/15-mail.sh)

- Postfix is **loopback-only** (`inet_interfaces = loopback-only`). That preserves the property the earlier msmtp-only design was protecting — a SIP edge must not be able to become an open relay — while providing a milter, which msmtp cannot support at all. `99-postflight.sh` asserts it rather than trusting it.
- **`non_smtpd_milters` is the load-bearing setting.** Mail submitted with `sendmail(1)` — which is how both FreeSWITCH's `switch_simple_email()` and the API's fax delivery send — never passes through `smtpd`. A config with only `smtpd_milters` signs nothing this host actually sends, and nothing reveals it until a receiver checks the signature.
- **Debian's Postfix is chrooted**, so the OpenDKIM socket must live at `/var/spool/postfix/opendkim/opendkim.sock` and be referenced from `main.cf` as `local:/opendkim/opendkim.sock`. `postfix` must be in the `opendkim` group, and `/etc/default/opendkim` must not put `SOCKET` back outside the chroot — it overrides `opendkim.conf`.
- The DKIM key is generated **once and never rotated**, same rule as `config_ensure_secret`: the public half is in DNS, and replacing the key breaks every signature until that record propagates.
- **SPF is not auto-published when relaying.** The relay provider's servers send the mail, and only they know which addresses those are; a guess would authorise the wrong senders. The step prints instructions instead. Direct delivery does get an `ip4:` record.
- **`SMTP_STARTTLS="off"` is implicit TLS (usually 465), and it must reach Postfix as `smtp_tls_wrappermode = yes`** (I12). Nothing read the setting before: Postfix waited for a plaintext greeting a 465 relay never sends, and every message was deferred. Wrapper mode applies to the relay only, never the direct-to-MX path. Step 15 refuses 465 with STARTTLS, and refuses an example.com/.net/.org `SMTP_FROM`, because an unattended install never passes through the wizard's checks.
- MX is behind `DNS_PUBLISH_MX`, default 0. Nothing here accepts inbound mail, so an MX pointing at this host makes every message to the domain bounce.
- **Port 25 egress is blocked on GCP permanently** and gated on AWS/Vultr, so the relay path (`SMTP_HOST` set, port 587) is the one that works in production. Direct-to-MX is the fallback, not the default assumption.

## Config templates (resources/conf)

A step deploys a config with `deploy_template "$TPL/<file>" <dst> [mode] [owner]`, which renders the template and hands it to `write_file` — so it keeps the same idempotence, backup and 0-changed/1-unchanged return, and callers still need the `|| true`.

- **A step that reads anything under `resources/` or a portal source directory must declare it in a `# step-inputs:` comment** (space-separated paths, relative to the repo root). `install.sh`'s `script_hash` folds those files into the step's marker checksum. Without the line, editing a template leaves the script byte-identical, the marker still matches, and the installer skips the very step that deploys the file you just changed. A declared path that does not exist aborts the run rather than being ignored.
- **The placeholder is `@NAME@`, not `${NAME}`.** These files are full of FreeSWITCH's own `${channel_var}` and `$${global_var}`, and Kamailio's `$rU`/`$fU`, all of which must reach the deployed file untouched. Any `$`-based syntax would mean escaping every one of them — which is exactly what made the heredocs this replaced so easy to get wrong.
- **Two adjacent placeholders leave no character between them.** `postgres://user:@PW@@HOST@` renders as `user:pwHOST` - the `@` you meant as the separator was consumed as the closing delimiter. Write `@PW@@@HOST@`. This kept Kamailio from starting on every fresh install (I26) while `kamailio -c` passed; `tests/installer-safety.py` now parses every rendered database URL.
- **An unset placeholder aborts the step, on purpose.** A literal `@FS_ESL_PASSWORD@` in a live SIP profile fails later, somewhere else, and looks like anything except a typo. So an optional setting has to be defaulted in the step *before* the `deploy_template` call — `FAX_SPOOL="${FAX_SPOOL:-/var/spool/qwixbox-fax}"`. This is the one thing the extraction got wrong, in `41-api-deploy.sh`, and it will recur: the old inline `${X:-default}` disappears silently when the heredoc moves out.
- Anything the old heredoc computed inline — a command substitution, a conditional block — becomes a named variable assigned in the step (`WEBRTC_RULE`, `TABLE_LINE`, `SIGNING_KEY_PARAM`). These read as unused to shellcheck, hence the `# shellcheck disable=SC2034  # read by name from the template` above each.
- `resources/freeswitch.service` is *not* one of these: systemd does not expand shell variables, so `${PREFIX}` is substituted by sed in `30-freeswitch.sh`. Keep the placeholder intact.

## Things to know when editing the step scripts

- Adding a step means adding it to the `STEPS` array in `install.sh` *and* creating `steps/<name>`. A step listed with no file warns and is skipped rather than failing the run, so the installer stays usable while the set is incomplete.
- Steps must be safe to re-run. Use the `lib/common.sh` helpers rather than raw `apt-get` / `cat >` — that is what makes a second run quiet instead of noisy and destructive.
- **Do not lock "other" out of `/usr/local/freeswitch`.** Anyone with sudo can read it anyway, so `o-rwx` adds no protection and only breaks routine inspection (this was a real bug: admins got permission denied everywhere). Writes are restricted through the `freeswitch` group; config dirs are setgid so admin-created files stay group-readable by the service.
- `31-freeswitch-config.sh` binds ESL to `127.0.0.1` with a generated password. The stock config listens on `::`, which fails outright on IPv6-less hosts and is far too open where it does work.
- Step 34 deploys SIP authentication, routing and protection. FreeSWITCH selects outbound routes and applies number translation; billing and alternate-carrier retry are absent. Enabled register-mode trunks are rejected until carrier registration/challenge handling exists.
- Kamailio needs a per-listener `advertise` on any host behind 1:1 NAT (GCP, EC2), or SIP breaks entirely — the interface holds a 10.x address while endpoints must be told the public one. Global `advertised_address` is not enough. `acc`/`missed_calls` `db_extra` columns need explicit ALTERs, outside the schema-creation guard, or accounting fails on every call.
- **Every step runs under `pipefail` (set by `lib/common.sh`), so `producer | grep -q` is a flaky test**: grep exits at the first match, the producer can die of SIGPIPE, and the pipeline reports failure. Postflight's port probe failed a listening port about one run in three this way (I10). Test a captured value instead (`grep -q pat <<<"$(ss -ltnu)"`), or let the producer decide (`awk '... { f = 1; exit } END { exit !f }'`). The same race left Debian's stock 2047-bit SSH moduli in place on every install (I32). A `bash -c "... | grep -q"` string is safe because the child shell does not inherit pipefail. `installer-safety.py` refuses any producer outside a one-line allowlist piped into `grep -q`.
- `99-postflight.sh` checks what the installer configured, per role. Its SSH check accepts step 10's root key-only login (`prohibit-password`, which `sshd -T` prints as `without-password`). Gate any new check on the `has_role` that installs the thing it checks, or a split-role host fails for something another host provides.
- The firewall is an `inet` table, so an address rule must name its family: `ip saddr` for IPv4 and `ip6 saddr` for IPv6. Step 11 splits `ADMIN_ALLOW_CIDR` that way. A single `ip saddr` set holding an IPv6 prefix made nft reject the whole ruleset, which left the host with no firewall at all (I12).
- Do not `git add -A` in this repo: it sweeps `.claude/` and local MCP config into the commit. Stage paths explicitly.

## Modules and dependencies (30-freeswitch.sh)

- The module selection (`FS_ENABLE_MODULES` / `FS_DISABLE_MODULES`) is the intent-carrying part of the script: it enables mod_callcenter, mod_cidlookup, mod_hiredis, mod_curl, mod_shout, mod_pgsql, mod_easyroute, mod_nibblebill, mod_fail2ban, mod_xml_curl and disables mod_skinny, mod_verto, mod_say_es, mod_say_fr, mod_av, mod_xml_rpc, mod_signalwire. Preserve this set unless asked to change it. Do not re-enable mod_v8 — it needs libv8-6.1-dev, gone from modern Ubuntu/Debian.
- Caching is Redis, via mod_hiredis. mod_memcache was deliberately removed (2026-07-29) — do not reintroduce it or `libmemcached-dev`.
- **This is a voice-only switch: video is off via `--disable-libvpx`.** FreeSWITCH otherwise builds `libs/libvpx` unconditionally (`enable_libvpx="yes"`), and on x86_64 that needs yasm/nasm. Disabling it is preferred over adding those assemblers — VP8/VP9 are dead weight here. It is safe: the core gates video on `SWITCH_HAVE_VPX`, mod_av is disabled, and mod_video_filter is off by default. If you ever re-enable video you must add `nasm yasm` to the apt list or x86_64 builds fail.
- Every enabled module needs its dev library in the apt list or the build dies mid-`make` (mod_hiredis → libhiredis-dev, mod_shout → libshout3-dev/libmpg123-dev/libmp3lame-dev). The module-path guard does **not** catch a missing dev lib — only a real build does. That is how the mod_memcache/libmemcached-dev mismatch surfaced.
- v1.11.1's `configure.ac` needs PCRE2 only (`PKG_CHECK_MODULES([PCRE2], [libpcre2-8 >= 10.00])`). `libpcre3-dev` is not required and was dropped deliberately — it is also gone from Debian 13, where it would fail the whole apt transaction.
- Module paths must match `build/modules.conf.in` exactly or the `sed` silently no-ops and the module keeps its default state. The non-obvious ones: `databases/mod_pgsql` (not formats/) and `say/mod_say_es` + `say/mod_say_fr` (not applications/). The script greps each entry first and aborts if a path moved upstream — keep that guard.

## The minimal config

- `make install` supplies vanilla configuration on a fresh install. Step 30 replaces only that fresh tree with `make config-minimal`; it preserves an existing hardened tree. It invalidates step 31 and applies it before starting FreeSWITCH, including an explicit `--only 30-freeswitch.sh` run. Never broaden credential-file modes during a rebuild.
- Disabling a module in `modules.conf` is only half the job: the minimal config's `autoload_configs/modules.conf.xml` still lists it (e.g. `mod_xml_rpc`), so FreeSWITCH logs `[CRIT] Error Loading module` on every start. The script comments out any autoloaded module that was not built — keep the two lists in sync.
- The "Codec Interfaces" section is **empty**, so only the core G.711 (PCMU/PCMA) codecs exist at runtime. `mod_opus` is enabled in stock `modules.conf` and builds fine but is never loaded unless explicitly added — that is what `FS_AUTOLOAD_ADD` does. Opus matters here because calls run over WiFi.
- A module autoloaded into the minimal config also needs its `<mod>.conf.xml`, which only ships in the vanilla tree. Without `opus.conf.xml`, mod_opus logs `Opening of opus.conf failed` and falls back to built-in defaults — losing `keep-fec-enabled`, the thing that makes Opus tolerate WiFi packet loss. The script copies the vanilla config for each autoloaded module.
- The stock event_socket config listens on `::`; on IPv6-less hosts (some Docker setups) mod_event_socket fails to bind until listen-ip is changed to 127.0.0.1.

## Service and permissions

- The unit runs as `User=freeswitch`, which needs write access to `$PREFIX/{db,log,run,recordings}` — so `chown -R freeswitch:freeswitch $PREFIX` is required, not a chown of some copy under `/etc`. FreeSWITCH reads `$PREFIX/conf`, never `/etc/freeswitch`, unless passed `-conf`; `/etc/freeswitch` is only a convenience symlink.
- `Type=forking` (FreeSWITCH daemonises under `-ncwait`) needs `PIDFile=${PREFIX}/run/freeswitch.pid` or systemd guesses the main PID.
- `ExecStop=${PREFIX}/bin/freeswitch -stop` (with `TimeoutStopSec`) lets FreeSWITCH tear down channels and flush CDRs instead of being SIGTERMed.

## Sounds

- Never use the `hd-`/`uhd-`/`cd-` targets. They chain downwards (`cd-sounds-install` → `uhd-` → `hd-` → 8k), so asking for 48k silently downloads all four rates (~383MB). Use the per-rate targets (`sounds-en-us-callie-48000-install`), which the Makefile's `.DEFAULT` rule resolves to a single tarball.
- `FS_SOUND_RATES` controls the set. 8000 (G.711/PSTN legs) + 48000 (Opus) is ~202MB; 8k-only prompts get upsampled for Opus callers and sound muffled.

## Build ordering and environment

- The `adduser` flags are chosen for Ubuntu 22.04's older adduser: use `--gecos` (not `--comment`) and keep the username last.
- Last verified 2026-07-29 on Debian 13.6 / systemd 257, tag v1.11.1, both architectures:

  - **x86_64 (emulated)** — full build succeeds in ~670s with no yasm/nasm error and libvpx never entered; started manually, FreeSWITCH reports ready with Opus present and no VP8/VP9/H264. The service could not be verified here (broken systemd in the emulated container, see above).
  - Not verified on Ubuntu 22.04 since these changes.

The current mail path uses Postfix/OpenDKIM; an amd64 verification pass for that path is still owed.

## Health and alerts (resources/conf/monitoring, steps/52-monitoring.sh)

- **`qwixbox-healthcheck` is the alerter** (I17). The 5-minute timer runs it; it emails `ALERT_EMAIL` and posts to `ALERT_WEBHOOK` from `/etc/qwixbox/alerts.env` (0600, since a webhook URL is a credential) when the set of failing check *names* changes or recovers, and repeats every 6h. Key a new check through `problem "<name>" "<detail>"`, and keep counts and dates in the detail, never in the name, or it re-alerts every run. Postfix refuses local delivery, so a local address is not a target.
- **Never pipe into `grep -q` in that script** (it runs under `pipefail`). grep exits at the first match, the producer dies of SIGPIPE, and the pipeline fails: `systemctl list-unit-files | grep -q` made every unit read as not installed, so no service was ever checked. Capture the output first, or use `systemctl cat`.
- **Backups alert through the same script.** `backup` fires when no `COMPLETE` snapshot is newer than 26h; `backup run` fires when the last `qwixbox-backup` run failed. Both are needed: a failed offsite copy still leaves a complete local snapshot. `qwixbox-backup` prunes only after a fully successful run, offsite copy included.
- `/health` is public: booleans and counts only. Its status counts FreeSWITCH and Kamailio, but Lua's D5 check reads `"database":true`, so a call-path outage does not also refuse peer forwards.
- `tests/installer-safety.py` runs the rendered script against stubbed services; the `HEALTH_*` overrides exist for it.

- **Role passwords go through `psql_secret` (`lib/common.sh`), never `psql -c`.** The shipped `log_statement = 'ddl'` writes every `ALTER ROLE ... PASSWORD` into the Postgres log in plain text, readable by `adm`; `psql_secret` sends the SQL on stdin after turning statement logging off for the session. `installer-safety.py` fails on a `psql ... -c` line mentioning a password.
- **`restore.sh` puts `/etc/qwixbox` back before the install runs**, so `config_ensure_secret` reuses every secret instead of generating new ones, then checks `ENCRYPTION_KEY` against a scratch restore (`src/cli/check-encryption.ts`) before replacing either database (docs/restore.md). A new secret or key file outside `/etc/qwixbox`, the DKIM keys and `/etc/letsencrypt` must be added both to `qwixbox-backup`'s archive and to restore.sh's pre-install extraction, or a restored host silently generates a new one.
- **After a database restore, run `src/cli/reconcile-kamailio.ts`** (docs/rollback.md). Projection jobs only act on rows they can name, so anything created after the dump keeps its Kamailio subscriber, trunk address and cached tenant until it is pruned. A new projected Kamailio table needs a line in `pruneKamailio()`.
- Writing a file in a sticky, group-writable directory owned by another user (`/var/log/postgresql`) fails even for root under `fs.protected_regular`, for any `O_CREAT` open — which `>` is. Use `dd conv=nocreat`.

## Review remediation invariants

- Runtime gateway secrets are read by systemd from `/etc/qwixbox/freeswitch.env` (0600). The public drop-in holds only an `EnvironmentFile` path; never put a secret back in `Environment=`. ESL XML is 0640 root:freeswitch. Old credential backups must stay restricted.
- Source hashing includes installer helpers and excludes node_modules, dist, private .env files and generated metadata. Both portal deploy steps declare their source directories. `invalidate_step` clears dependent markers when an upstream step replaces their configuration.
- `bun_as` takes an executable and separate arguments, never a shell command string. It preserves apostrophes and argument boundaries.
- Tenant create and PATCH share runtime validation. XML escaping does not stop FreeSWITCH variable expansion. Exact DID ownership is globally unique, including disabled routes; do not silently reassign it during an upgrade.
- `src/app.ts` assembles the production API without starting background timers; integration tests import that app. `src/index.ts` owns startup workers. Preserve expected HTTPException responses and tenant-safe database conflict errors.
- Backups fail if required encryption config cannot be archived. Retention follows a successful verified snapshot/offsite copy; a successful backup is not proof of a restore.
